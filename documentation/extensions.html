Build an extension

Use the Rust SDK or implement the versioned wire protocol.

Minimal Rust provider

Create a binary crate with these dependencies. Adjust the SDK path relative to your crate.

[dependencies]
anyhow = "1"
starfold-preview-protocol = { path = "../starfold/extensions/protocol" }
use anyhow::{ensure, Result};
use starfold_preview_protocol::{Presentation, Request};
use std::{ffi::OsString, os::unix::ffi::OsStringExt, path::PathBuf};

fn main() -> Result<()> {
    let mut content: Option<Presentation> = None;
    starfold_preview_protocol::serve(
        "notes", "1", &["documents"], |request| {
            match request {
                Request::Open { path, .. } => {
                    let path = PathBuf::from(OsString::from_vec(path));
                    ensure!(std::fs::metadata(&path)?.is_file(), "Regular files only");
                    content = Some(Presentation {
                        kind: "Notes example".into(),
                        fields: vec![("Name".into(),
                            path.file_name().unwrap_or_default().to_string_lossy().into())],
                        ..Default::default()
                    });
                }
                Request::Input { .. } => {} // No consumed keys in this example.
                _ => anyhow::bail!("Unsupported request"),
            }
            Ok((content.clone().ok_or_else(|| anyhow::anyhow!("Open first"))?, vec![]))
        },
    )
}

The SDK handles hello/version negotiation, framing, scope echoing, close/cancel and presentation validation. Your callback handles Open and Input. It returns one presentation and an optional binary attachment for each request.

Register it

[[preview.extensions.providers]]
id = "notes"
command = ["/absolute/path/to/notes-helper"]
extensions = ["note"]
mime_types = []
priority = 0

Commands are argv arrays, with no shell interpolation. Provider IDs must be unique. Register only trusted programs; supervision is not an operating-system sandbox. Helpers are never discovered from the directory being browsed.

Wire format

Each frame contains a big-endian u32 JSON length, a big-endian u32 binary length, JSON bytes and then binary bytes. Maximum lengths are 1 MiB and 32 MiB. Standard output contains protocol frames only; diagnostics belong on standard error.

{
  "session": 42, "generation": 7, "sequence": 3,
  "message": {
    "type": "input",
    "input": {"type": "key", "key": "j"}
  }
}

Every reply echoes session, generation and sequence exactly. The sequence is a request/reply pair, not an unsolicited event stream. Hello negotiates protocol version 1. Open supplies raw Unix filename bytes, budgets and a viewport. Input supplies keys, actions, pointer coordinates, page requests or a changed viewport. Close and Cancel end the session.

Presentation choices

  • Fields and text pages: plain data styled by FOLD; never terminal escape sequences.
  • Raster: one raw RGBA8 attachment, exactly width × height × 4 bytes.
  • Native surface: bounded KIT drawing primitives and hit regions. Provide text as a fallback for cell clients.
  • Media: metadata and typed media actions; video bytes do not travel through the generic extension attachment stream.

Interactive editor sessions

An editor requires the host's negotiated editor capability. Return interactive: true to receive focused keyboard input, and modified to report buffer state. Input::Paste carries bounded pasted text. Return interactive: false only when the editor closes. The host queues editor input in order and preserves the session across file writes. Clean buffers can follow the cursor. Modified buffers prompt before replacement, closing or quitting; handle Input::Action values editor-save and editor-discard and report the resulting modified state. A failed save must leave the editor live and modified. Advertise reopen in the helper handshake to accept repeated Open requests within the same session. The host can keep one clean reusable editor idle across other preview types; closing Preview kills both active and idle helpers. Older hosts must be refused before opening an editor.

Input and lifecycle

Advertise only the keys you consume. FOLD routes them while Preview has focus and retains application shortcuts. Surface hit actions return to the extension. Terminal pointer precision remains cell based. Keep sessions responsive: a deadline or changed selection terminates and reaps the helper process group, including children. A failed selected helper reports an error; FOLD does not silently try the next lower-ranked executable.

Resources are bounded by Open limits and protocol validation. Respect the host text/cache/image budgets before allocating or decoding. File identity and generation checks prevent stale results from replacing a newer selection. The UI acknowledges durable media actions after consuming them.
