Embedded Neovim

Read/write editing inside Preview, with Neovim owning the editor UI.

starfold-preview-nvim launches Neovim with --embed and attaches an RGB screen grid through its MessagePack-RPC API. Neovim owns buffers, modes, cursor movement, syntax highlighting, splits, command line, searches, undo and file writes. FOLD places the returned native surface inside Preview.

Configure the extension

[[preview.extensions.providers]]
id = "nvim"
command = ["/absolute/path/to/starfold/target/release/starfold-preview-nvim", "/absolute/path/to/nvim"]
extensions = ["txt", "md", "rs", "py", "c", "h", "cpp", "go", "sh", "lua", "toml", "yaml", "yml", "json", "js", "ts", "tsx", "jsx", "html", "css", "log"]
mime_types = ["text/*", "application/json", "application/xml", "application/javascript"]
priority = 0

The helper is included in default workspace builds and release packages. Neovim is an installed runtime dependency. Its executable path is optional; omitting it uses nvim on PATH. Use matching current FOLD and helper versions: the helper requires the negotiated editor capability and refuses older hosts that cannot protect an editor session.

Use it

InputBehavior
Click PreviewFocus the editor; keys and mouse input go to Neovim.
i, Esc, v, :, /Normal Neovim insert, normal, visual, command and search modes.
:wSave the actual file.
:wqSave and close the editor.
:qClose; Neovim follows your configured unsaved-change handling.
:q!Explicitly discard unsaved changes and close.
Tab / Shift+TabMove focus between browser panes and Preview. Ctrl+I inserts a Neovim tab.
F6Return focus to the browser; clean previews follow its cursor.
PasteForward bracketed paste to the editor, capped at 64 KiB.

Clean editor buffers follow the browser cursor automatically. Neovim and LazyVim stay loaded across text-file changes, replacing clean preview buffers rather than accumulating tabs, and one clean editor session can remain idle while other file types use their own previews. Closing Preview or STAR/FOLD reaps it. If you have edits, switching files, closing Preview, switching tabs or quitting opens a prompt: s saves and continues, d discards and continues, and Esc cancels. Failed saves keep your editor open. Ctrl+C quits STAR/FOLD even with editor focus, using the same unsaved-change prompt. Alt+T and Alt+Shift+T change the STAR/FOLD theme while LazyVim retains its own colorscheme. Keyboard input is queued in order with one request in flight; refresh notifications cannot discard typing.

Embedding architecture

FOLD: scoped input→Helper: Preview v1→Neovim: MessagePack RPC

The helper handles Neovim grid_resize, grid_line, grid_scroll, highlight, cursor and mode events. It returns a bounded KIT surface and a plain-text grid fallback. Color/highlight runs become primitives, keeping the Neovim status line and command line inside Preview. It does not use a terminal emulator, webview or terminal escape stream. The grid uses fixed 8 × 18 pixel cells and a 13 pixel font, and is capped at 8,192 cells and surfaces remain within the Preview protocol budgets.

// Attach the real Neovim UI; no second terminal reader.
nvim_ui_attach(columns, rows, { rgb = true, ext_linegrid = true })

// Forward user input and parse redraw notifications.
nvim_input("i")
nvim_paste("text", false, -1)
nvim_input("<Esc>")

// Resize requests are notifications, so modal prompts cannot block the host.
local filename, recovery, channel = ...
vim.o.modeline = false
vim.o.exrc = false
vim.o.directory = recovery .. '//'
vim.o.updatecount = 1
vim.api.nvim_cmd({cmd='edit', args={filename}}, {})
vim.bo.readonly = false
vim.bo.modifiable = true
-- Buffer events report modified state back over the private RPC channel.
-- The complete bridge also preserves swap data when the buffer is modified.

Theme and rendering

Neovim keeps your configured colorscheme, including its default foreground and background. Neovim owns syntax highlight colors; its highlight attributes are translated into surface colors, bold text and reverse video. The cursor is outlined. Underlines, italics and cursor animation are not currently reproduced. Cell clients receive a plain-text screen fallback with the same editor input, without syntax-color rendering.

File and recovery behavior

This opens the full source file, not a truncated snapshot. Files larger than the host text budget (capped at 512 KiB) are refused rather than risking a partial save. Initial files and pathnames must be UTF-8; NUL-containing inputs are rejected. Neovim performs writes and normal external-change checks. Saving a file changes its identity without causing FOLD to reopen the editor.

Your normal Neovim configuration and plugins load, including LazyVim, its key bindings and its colorscheme. Modelines and local vimrc are disabled. Swap recovery data goes to $XDG_STATE_HOME/starfold/nvim-recovery, or ~/.local/state/starfold/nvim-recovery, with private directory permissions. Normal Neovim exit cleans its swap files; a forced process exit leaves recovery data for nvim --cmd 'set directory=~/.local/state/starfold/nvim-recovery//' -r /path/to/file. Use your actual XDG state path if configured.

Neovim commands retain their normal user privileges. The child is supervised and its process group is reaped with Preview. Physical desktop typography and interaction remain separate checks from the automated tests.

Build and test

CARGO_NET_GIT_FETCH_WITH_CLI=true nix develop -c cargo build --release --features terminal-graphics
STARFOLD_TEST_NVIM=/absolute/path/to/nvim \
STARFOLD_TEST_NVIM_HELPER=/absolute/path/to/starfold/target/debug/starfold-preview-nvim \
CARGO_NET_GIT_FETCH_WITH_CLI=true nix develop -c cargo test --workspace --all-features

Tests cover real insert/paste/save/discard behavior, dirty-buffer quit refusal, resize and configured colors, bounded grid events, burst keyboard input, clean-file navigation, session reuse, save/discard/cancel prompts, failed writes, global theme keys and save continuity. External-runtime tests are skipped unless the indicated environment variables are set.
