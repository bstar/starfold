Themes and ownership

A shared palette, with pane chrome kept outside extensions.

What the host sends

{
  "width": 800,
  "height": 600,
  "foreground": "#cdd6f4",
  "background": "#1e1e2e"
}

Open includes this viewport. Input::Viewport updates it when dimensions or colors change. Width and height are pixel dimensions of the available content. Providers should redraw their content and discard size-dependent caches when necessary.

Who chooses colors?

PresentationTheme behavior
Plain text/fieldsFOLD applies its semantic theme roles.
Native surfaceThe extension explicitly colors its primitives using the supplied foreground/background. The host validates and places the surface.
PDF rasterHayro preserves document colors and uses white paper; it does not recolor PDF content to match the app.
Movie contentPreserves media colors.
Movie timeline/detailsFOLD uses panel background, accent and muted text roles.
AMP controlsAMP receives seven roles: background, foreground, muted, accent, selected, border and error.

The general extension contract currently exposes only foreground and background, not AMP's richer palette. A native surface must provide literal colors; there is no automatic substitution of semantic tokens.

Example surface

let mut surface = starkit::native_surface::Surface::new(
    width, height, viewport.background.clone(),
);
surface.text(
    starkit::native_surface::PixelRect::new(0, 0, width, 20),
    "Read-only content", &viewport.foreground, 14, false,
);
// Return the surface plus a TextPage fallback inside Presentation.

FOLD owns borders, titles, focus indicators, pane padding, status/footer and popup layers. Keep extension primitives inside the supplied content area. Do not recreate terminal chrome or emit terminal controls.
