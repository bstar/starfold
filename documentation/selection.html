File-type hierarchy

Specific rules beat broad rules; priority resolves peers.

Providers may overlap. Selection is deterministic and does not depend solely on registration order.

Selection order

  1. Explicit suffix override. Case-insensitive; the longest compound suffix wins.
  2. Explicit MIME override. Exact MIME, then family (text/*), then */*.
  3. Configured provider suffix. Longest matching suffix, such as tar.gz before gz.
  4. Configured exact MIME. Such as text/plain.
  5. Configured MIME family. Such as text/* or video/*.
  6. Configured catch-all. */*.
  7. Bundled PDF/video provider, then built-in preview handling.

Within an equally specific configured match, higher integer priority wins. Equal priorities preserve configuration order. A provider listing several rules is ranked by its best match. Priority never makes a broad rule outrank a more specific rule. Extensions may include a leading dot; matching is case-insensitive and requires a dot before the suffix.

A broad NVIM provider and a specialist

[[preview.extensions.providers]]
id = "nvim"
command = ["/absolute/path/to/starfold-preview-nvim", "/absolute/path/to/nvim"]
mime_types = ["text/*"]
priority = 0

[[preview.extensions.providers]]
id = "markdown"
command = ["/absolute/path/to/markdown-preview"]
extensions = ["md", "markdown"]
priority = 0

[preview.extensions.extension_overrides]
"txt" = "nvim"

[preview.extensions.overrides]
"application/pdf" = "pdf"

Disable and classification behavior

disabled removes ordinary provider candidates. An explicit override targeting a disabled provider blocks that choice and leaves metadata/built-in fallback behavior; it does not choose another extension. Disabling bundled PDF/video also prevents their old in-process preview route. PDF headers are recognized regardless of filename. Other known MIME types come from filenames; an unknown type becomes text/plain only for a nonempty UTF-8 header without binary controls. This is bounded classification, not comprehensive content sniffing.

Directories and symlinks retain their dedicated built-in handling. Catch-all rules apply to eligible regular-file previews and should be used deliberately. A rule chooses a provider, not an error-recovery chain.
